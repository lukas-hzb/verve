# Security Policy

## Supported Versions

Security fixes are applied to the current `main` branch and the hosted deployment at [verve.hzb.app](https://verve.hzb.app). Older commits, private modifications, and third-party deployments are not supported.

## Report a Vulnerability

Use [GitHub's private vulnerability reporting](https://github.com/lukas-hzb/verve/security/advisories/new) to report a suspected vulnerability. Do not open a public issue or include credentials, personal data, access tokens, database contents, or working exploits in public discussions.

Include the affected route or feature, required account state, reproduction steps, expected impact, and any suggested mitigation. Use only accounts and data you own or are explicitly authorized to test, and avoid automated or high-volume testing against the hosted application.

Relevant reports include authentication or authorization bypasses, cross-account data exposure, injection, cross-site request forgery, unsafe redirects, OAuth flaws, and disclosure of secrets or personal information. Issues in third-party services without a demonstrated impact on Verve should be reported to the responsible provider.

Reports are reviewed as availability permits. Please allow time for investigation and coordinated remediation before disclosing vulnerability details.
